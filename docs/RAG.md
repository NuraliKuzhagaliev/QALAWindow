# How recommendations work

The collector downloads public Astana POIs and a pedestrian network. Each POI has a stable OSM ID and field-level receipts. Multilingual lexical retrieval combines distance pruning, local aliases, query terms, category synonyms and inverse document frequency. A small diversity reserve prevents all candidates being cafes simply because cafes have more complete hours. There is no vector database or embedding claim.

The deterministic planner checks strict attributes and evidence, routes up to eight candidates, and evaluates up to 400 ordered one-to-three-stop sequences. It includes every outward/inter-stop/return leg, conservative maximum dwell estimates and exactly one explicit buffer. Hours are checked through the full arrival/departure interval using opening_hours. Unresolved holiday rules, malformed hours and missing data remain unknown. Strict access cannot pass without both entrance and route evidence. Unknown indoor status counts toward the outdoor limit.

Walking routes come from the collected OSM network using Dijkstra, with a disclosed 1.15 m/s modeled speed, or from the configured HeiGIT foot-walking matrix/directions adapter. Haversine is only spatial pruning, a graph edge length or a disclosed snap connector, never a replacement route. Snaps over 100 m fail. Snaps above 30 m make the plan conditional. Straight connectors are not drawn as roads. Route access/crossings are unverified. Source network coverage can be disconnected.

Plans rank max-min group preference match before total preference match, then category diversity, evidence and walking economy. These scores are neutral matches, not happiness probabilities. Results are best among the retrieved candidate set, not every possible Astana route. Group preferences are processed locally by default; group mode uses the same solver in the browser and does not send individual profiles to the server or model.

Gemini 3.5 Flash Lite receives only selected public POI facts, typed interests and the language. Exact coordinates and raw user query text are omitted. It generates structured choices of approved short reasons and suggested activities. IDs, choice ranges, duplicates and extra fields are validated. This deliberately constrained generation avoids arbitrary factual prose: factual badges and times always come from source fields or calculations. It is real retrieval plus a real model request, with bounded, controlled language generation. Generic phrasing is a current quality limitation. Deterministic fallback is visibly labeled local solver, never live AI.

The browser receives validated facts before asking for an explanation by opaque request ID. The server keeps the exact validated plan for at most two minutes and never accepts client-created model facts. Model result choices are cached for 15 minutes by public bundle/language/context. The limiter allows at most 12 model requests per minute and two concurrent requests, leaving headroom under the operator's reported 15 RPM limit. A 429 activates cooldown, with no automatic retry of a daily-exhausted model. No alternate paid model is called. Provider failures leave factual cards usable.

Real trace: `tests/evidence/real-retrieval-trace.json`. Live quality evidence: `tests/evidence/live-quality.json`. Synthetic error fixtures are distinct from real collected records. There are no hidden prerecorded answers.
